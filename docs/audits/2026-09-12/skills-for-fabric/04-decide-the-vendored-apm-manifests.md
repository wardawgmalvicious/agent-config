## D-1 — does "vendored verbatim" include a packaging manifest?

**Open question. Put this to the user; do not decide it while making the
currency edit.**

The case for adding it: "verbatim" is the claim the notes make, the file
is small and MIT-licensed like the rest, and a future re-sync diff is
cleaner when the local directory matches upstream's exactly — which is
precisely what that note instructs ("diff against upstream and re-apply
this section only").

The case against: Claude Code reads `SKILL.md`, not `apm.yml`. The file
exists to drive `apm install`, an acquisition route this repo does not
use — these two skills arrived by hand-vendoring and are deployed by
`scripts/link-claude.ps1`. Carrying it adds a generated file that
upstream regenerates (`# Generated by … do not edit by hand`) and that
nothing here reads, and its `description` field would then sit in the
directory alongside the `SKILL.md` frontmatter `description` that is the
actual trigger mechanism — two descriptions, one live, with no check
keeping them consistent.

**Either answer is defensible and the edit in D-2 is required by both.**

**Constraint if it is added.** `scripts/lint-frontmatter.py` and
`scripts/lint-skill-scopes.py` both select on `SKILL.md`, so an
`apm.yml` is unlinted — nothing would catch it drifting from upstream or
from the sibling `SKILL.md`. Note that in the vendoring note rather than
leaving it implicit.

**Constraint either way — do not copy the `dependencies` block into a
Claude MCP config.** It carries a per-server `tools: ["*"]` key, and
upstream's own `0.3.11` changelog reports that Claude Code **rejects** a
per-server `tools` key in `mcpServers`. In `apm.yml` it is a field of
APM's dependency schema, not Claude's, so it is harmless where it sits.
Neither `claude/mcp/*.template.json` nor `.vscode/mcp.template.json`
uses such a key today (grepped 2026-09-12); keep it that way.

## D-2 — neither note records a dated currency check

**Symptom.** Both notes pin the vendoring at `v0.3.13` / `b8d541c` and
stop there. Nothing says whether upstream has moved since, so a reader
has to re-derive it — which costs the four listings this audit spent.

**Cause.** The note was written as a provenance record, and provenance
does not go stale. Currency does, and the two were never separated.

**Fix.** Add one dated line to each note. The existing `v0.3.13` /
`b8d541c` pin is **correct and must not change** — the local bytes are
still exactly that commit's. What is being added is the confirmation:
content unchanged upstream through `v0.3.16` (`f1802196`), verified
2026-09-12 by blob and tree SHA, with the `apm.yml` addition named and
its disposition recorded per D-1.

**Constraint.** Do not write that the skills were "re-synced" or
"updated to v0.3.16". Nothing was re-synced; upstream simply has not
changed the text since `b8d541c`. Overstating it would make the next
re-sync diff against the wrong base.
