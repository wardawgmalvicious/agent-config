# Microsoft Learn references — Fabric catalog governance

Curated set of the pages behind this skill — the OneLake catalog Govern
tab, domains, endorsement, tags, sensitivity labels, ownership, and the
Admin and Core REST surfaces that reach them. Load on demand when you
need the authoritative spec for one endpoint or concept.

All were fetched on 2026-09-11. Per-endpoint permissions, limits and
response shapes are summarised in [endpoints.md](endpoints.md); this
file is the link bundle behind it.

## The Govern tab and the catalog

- [Govern Fabric data](https://learn.microsoft.com/fabric/governance/onelake-catalog-govern) — the three insight areas and their exact names, admin versus data-owner views, the daily Admin Monitoring Storage refresh against a per-open refresh for data owners, the Pro-license requirement for the admin monitoring workspace, and the considerations list: subitems, cross-tenant and guests, Private Link, third-party workload items. Also the warning never to modify the autogenerated report or semantic model.
- [OneLake catalog overview](https://learn.microsoft.com/fabric/governance/onelake-catalog-overview) — the Explore / Govern / Secure split, and the catalog's embedding in Teams, Excel and Copilot Studio.
- [Secure your data](https://learn.microsoft.com/fabric/governance/secure-your-data) — the Secure tab. Workspace Admins and Members see full access data; Contributors and Viewers see only their own.

## Domains

- [Domains](https://learn.microsoft.com/fabric/governance/domains) — the role model: what a Fabric admin, a domain admin and a domain contributor may each do; that a domain contributor must also be a workspace admin to assign; that subdomains have no admins of their own; that a default domain never overrides an existing assignment; that domain assignment does not affect item visibility or access; and that bulk assignment excludes *My workspaces*.
- [Domain management tenant settings](https://learn.microsoft.com/fabric/admin/service-admin-portal-domain-management-settings) — "Allow tenant and domain admins to override workspace assignments (preview)", **enabled by default**, and "The domain REST APIs respect this setting".
- [Admin Domains REST operations](https://learn.microsoft.com/rest/api/fabric/admin/domains) — the operation index. Individual pages carry the `?preview=false` requirement, the 40/256 character caps, and the per-operation rate limits.
- [Assign Domain Workspaces By Ids](https://learn.microsoft.com/rest/api/fabric/admin/domains/assign-domain-workspaces-by-ids) — the override sentence, the 10-per-minute limit, and the synchronous 200.
- [Delete Domain](https://learn.microsoft.com/rest/api/fabric/admin/domains/delete-domain) — two error codes and nothing about cascade. The gate in SKILL.md §6 exists because of what this page does *not* say.
- [Role Assignments Bulk Assign](https://learn.microsoft.com/rest/api/fabric/admin/domains/role-assignments-bulk-assign) — plural `type` values, the `EntireTenant` restriction, and the already-assigned error code.
- [Assign To Domain (Core)](https://learn.microsoft.com/rest/api/fabric/core/workspaces/assign-to-domain) — the non-admin route: both permissions required, and the two error codes that say which is missing.

## Protect — sensitivity labels and DLP

- [Bulk Set Labels](https://learn.microsoft.com/rest/api/fabric/admin/labels/bulk-set-labels) — the real path (`/v1/admin/items/bulkSetLabels`), user-only identity support, 25/hour and 2,000 items, the label-policy requirement, `delegatedPrincipal`, `assignmentMethod`, the per-item status enum, and labelling of autogenerated items.
- [Set and remove labels via API](https://learn.microsoft.com/fabric/governance/service-security-sensitivity-label-inheritance-set-remove-api) — the same limits stated from the Power BI side.
- [Domain default sensitivity label](https://learn.microsoft.com/fabric/governance/domain-default-sensitivity-label) — the gating tenant setting, the override table (manual labels never overridden), the two moments it applies, and the lack of support for deployment pipelines and Git integration.
- [Data loss prevention for Fabric](https://learn.microsoft.com/purview/dlp-powerbi-get-started) — DLP policies are authored in the Purview portal; there is no Fabric REST route.

## Trust — endorsement, tags, curation

- [Endorsement overview](https://learn.microsoft.com/fabric/governance/endorsement-overview) — who can promote, certify and apply master data; the tenant-level enablement; and delegation of certification to domain admins.
- [Enable certification](https://learn.microsoft.com/fabric/admin/endorsement-certification-enable) — the certifier field "accepts security groups only. You can't enter named users", and the delegation checkbox that grants domain admins override of every tenant-level certification setting.
- [Tags overview](https://learn.microsoft.com/fabric/governance/tags-overview) — 10,000 tags per tenant, 10 per item and per workspace counted independently, the several-hour propagation delay, and the domain-move side effect on domain-level tags.
- [Create and manage tags](https://learn.microsoft.com/fabric/governance/tags-define) — deleting a tag removes it from every item that carries it.
- [Apply Tags (Core)](https://learn.microsoft.com/rest/api/fabric/core/tags/apply-tags) — contributor-or-higher, 25 per minute.

## Inventory, ownership and identity

- [Admin List Items](https://learn.microsoft.com/rest/api/fabric/admin/items/list-items) — the Preview banner, the 10,000-record page cap and its fixed type order, `state: active` only, and the field list that contains no label, endorsement or domain.
- [Take ownership of Fabric items](https://learn.microsoft.com/fabric/fundamentals/item-ownership-take-over) — "there's no API support for changing ownership of Fabric items", no takeover as a service principal, the child-item cascade, and the mirrored items that can never change owner.
- [Associate an item identity](https://learn.microsoft.com/rest/api/fabric/articles/item-management/associate-item-identity) — the supported item types, the Write-on-all-children requirement, the stop-on-child-failure behaviour, and the type-qualified URL that errors.
- [Catalog Search](https://learn.microsoft.com/rest/api/fabric/core/catalog/search) — Preview, the excluded item types, and the six fields it returns. Discovery belongs to `fabric-cli` / `fabric-rest-api`; this page is here to bound what a search-based count can claim.

## Mechanics that bound a sweep

- [Throttling](https://learn.microsoft.com/rest/api/fabric/articles/throttling) — the unified 200-calls-per-60-seconds quota per identity, and the two distinct 429 causes.
- [Pagination](https://learn.microsoft.com/rest/api/fabric/articles/pagination) — `continuationUri` and `continuationToken` are removed or null when the walk is complete.
- [Enable service principals for admin APIs](https://learn.microsoft.com/fabric/admin/enable-service-principal-admin-apis) — the two separate tenant switches, read-only and update, each bound to a security group.
- [Get Activity Events](https://learn.microsoft.com/rest/api/power-bi/admin/get-activity-events) — one UTC day per call, within the last 28 days.
- [Post Workspace Info](https://learn.microsoft.com/rest/api/power-bi/admin/workspace-info-post-workspace-info) — 1 to 100 workspace IDs per scan, 500 per hour, 16 concurrent.
- [Get Refresh History In Group](https://learn.microsoft.com/rest/api/power-bi/datasets/get-refresh-history-in-group) — the Write-permission requirement that makes a Viewer's staleness check impossible.
